# 备份与恢复

> 2026-10-03 落地。此前 MySQL(RDS) / Milvus / Redis 全部零备份——一次磁盘故障即不可逆丢失（Milvus 含知识图谱 + RAG 向量库）。

## 覆盖范围

| 数据 | 方式 | 说明 |
|------|------|------|
| MySQL（RDS） | `mysqldump --single-transaction` 逻辑全量，gzip 落盘 | 若 RDS 已开云快照，本脚本为**逻辑备份兜底**（可精确恢复单库，不受快照周期限制） |
| Milvus | 停机快照：`docker stop` 三容器 → `tar` volumes → 重启 → healthz 等待 | 含知识图谱（kg_entity/kg_triple）+ RAG 向量库；停机窗口约 1~3 分钟，凌晨低峰执行 |
| Redis | 不备份 | 缓存/会话性质，重启即重建 |
| RabbitMQ | 不备份 | 多 Agent 任务队列，丢失仅影响在途任务 |

## 安装（应用服务器 47.110.234.58）

```bash
# 方式一：全新安装（deploy.sh install 会自动上传 + 装 cron）
bash scripts/deploy.sh install

# 方式二：已装环境补装
scp -i ~/.ssh/core.pem scripts/backup.sh scripts/restore.sh root@47.110.234.58:/opt/app/
ssh root@47.110.234.58 'chmod +x /opt/app/backup.sh /opt/app/restore.sh && /opt/app/backup.sh --install-cron'
```

cron：每日 **04:00** 执行，日志 `/opt/app/logs/backup.log`（cron 侧 `backup-cron.log`）。

## .env 配置（可选，均有默认值）

```bash
BACKUP_DIR=/opt/app/backups          # 本地备份目录
BACKUP_RETENTION_DAYS=7              # 本地保留天数
BACKUP_REMOTE_HOST=root@112.124.106.108   # 异机目标（强烈建议配置），空 = 仅本地
BACKUP_REMOTE_DIR=/opt/app/backups   # 异机目录
```

**异机复制依赖两台服务器 ssh 互信**（应用服务器 → 入口服务器）：
```bash
# 在应用服务器上执行一次
ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_ed25519
ssh-copy-id root@112.124.106.108
```
> ⚠️ 入口服务器为低配机，Milvus 备份可能达 GB 级——若磁盘吃紧，可将 `BACKUP_REMOTE_DIR` 指向挂载盘或仅同步 mysql 目录（rsync 手工）。

## 手动执行

```bash
/opt/app/backup.sh                 # 全量（MySQL + Milvus 停机快照）
/opt/app/backup.sh --online        # Milvus 不停机（一致性风险自担，仅应急用）
/opt/app/backup.sh --mysql-only    # 仅 MySQL
```

每份备份落盘后自动 `gzip -t` 校验 + 空文件检测；MySQL 备份失败常见原因：`mysqldump` 未装（`yum install mariadb-server`）、RDS 白名单未放行应用服务器 IP。

## 恢复（restore.sh，事故时用）

```bash
/opt/app/restore.sh list                                   # 列出可用备份
/opt/app/restore.sh mysql  test_data-20261003-040000.sql.gz   # MySQL 整库恢复（覆盖）
/opt/app/restore.sh milvus milvus-20261003-040000.tar.gz      # Milvus 恢复（清空后解压）
```

- MySQL 恢复后**无需重启 Java 服务**（连接池自动重连）；Milvus 恢复后建议 `bash /opt/app/restart-llm.sh` 让客户端重建连接。
- 两类恢复均为**破坏性操作**：mysql 覆盖同库数据、milvus 清空 `/opt/app/milvus/volumes`——脚本内置交互确认，`--yes` 可跳过（仅限脚本化演练）。

## 演练建议（每季度）

1. 入口服务器或异机取最近一份备份 → 应用服务器临时目录
2. `restore.sh mysql` 恢复到**临时库名**（先改 dump 头部库名或建影子库）核对行数
3. `restore.sh list` 确认 Milvus 备份 gzip 校验可过（不必真恢复，恢复需停图谱服务）

## 已知限制

- Milvus 停机快照窗口内 chat-llm 的 RAG 问答 / 知识图谱写入不可用（约 1~3 分钟，每日 04:00）
- 异机副本与本地保留期相同（7 天）；更早历史依赖 RDS 云快照（如已开启）
- `--online` 模式 tar 运行中的 etcd/minio 有一致性风险，可能恢复出损坏 collection——仅限停机不可接受时的应急选项
