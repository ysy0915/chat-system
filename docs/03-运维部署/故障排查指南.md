## 二、常见问题

### 2.1 前端页面加载失败 / 白屏

**可能原因**：
1. Nginx 静态资源未更新
2. 前端 dist 文件未上传或路径不对
3. 浏览器缓存旧版本 JS

**排查步骤**：
```bash
# 检查主服务器静态资源是否存在
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "ls -la /opt/app/static/chat/"

# 重新上传前端
cd /Users/apple/IdeaProjects/chat-system-project/frontend
npm run build
scp -r -i "/Users/apple/Downloads/我的密钥.pem" \
  dist/* root@112.124.106.108:/opt/app/static/chat/
```

### 2.2 请求返回 401

**可能原因**：
1. JWT Token 过期
2. 接口不在 SecurityConfig 白名单中
3. 前端 `localStorage.auth_token` 被清除

**排查步骤**：
```bash
# 查看 Nginx 日志确认哪些接口返回 401
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "tail -100 /var/log/nginx/access.log | grep ' 401 '"
```

**修复**：如接口应为公开访问，在 `SecurityConfig.java` 添加：
```java
.requestMatchers("/api/v1/your-path/**").permitAll()
```

### 2.8 JDK 26 编译失败 (cannot find symbol)

**现象**：`mvn clean install` 报 `cannot find symbol: variable Locale / HashMap / ModelConfig` 等

**原因**：JDK 26 更严格检查显式 import，不再允许未声明 import 的类型引用

**修复**：为报错文件添加对应的 `import` 声明：
```java
import java.util.Locale;           // Locale.ROOT
import java.util.HashMap;          // new HashMap<>()
import java.util.ArrayList;        // new ArrayList<>()
import java.util.HashSet;          // new HashSet<>()
import java.util.Arrays;           // Arrays.asList()
import java.util.Set;              // Set<String>
```

**已修复文件** (2026-08)：
- `chat-core`: `ErrorType.java`, `FileContentExtractor.java`, `DocumentParser.java`, `TreeHoleService.java`, `TaskClassifier.java`
- `chat-media`: `MediaGenController.java`

## 4. 知识库管理 (RAG)

### 4.1 知识库列表显示 internal server error

**排查**：

```bash
# 1. 查看 chat-web 最近错误
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -i 'ERROR\|Exception' /opt/app/logs/web-8081.log | tail -10"

# 2. 查看 chat-llm 最近错误（RAG 运行时已迁至 chat-llm :9095）
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -i 'ERROR\|Exception' /opt/app/logs/llm-9095.log | tail -10"
```

**常见原因**：

| 错误 | 原因 | 解决 |
|------|------|------|
| `MismatchedInputException: Cannot deserialize Array as Map` | `CoreClient` 用了 `Map.class` 接收数组返回值 | 改为 `Object.class`，已修复 |
| `403 "访问被拒绝"` (非 "仅管理员可操作知识库") | `chat-web` → `chat-llm` 缺少 `User-Agent` 头，被 `IpRateLimitInterceptor` 拦截 | `authHeaders()` 中加 `User-Agent: chat-web`，已修复 |
| `403 "仅管理员可操作知识库"` | JWT 中 `role` 不是 `admin` | 数据库 `UPDATE users SET role='admin' WHERE name='xxx'`，重新登录获取新 Token |
| `404 not found` / 路由不存在 | ① `chat-web` 没有 `/api/v1/rag/*` 代理路由；② chat-llm 未开启 `app.rag.enabled`（`/internal/rag/*` 与 `/api/v1/rag/*` 条件注册未生效） | ① 检查 `KnowledgeBaseController`；② 检查 `/opt/app/.env` 中 `RAG_ENABLED=true` |
| `500 Column 'invoke_type' cannot be null` | 新增提供商时未传 `invokeType`，MyBatis 显式插入 NULL 绕过 DB `DEFAULT 'rest'` | `LlmProviderAdminService.toRow()` 已补默认值 `"rest"`；升级 chat-llm jar |
| `/api/v1/llm/admin/**` 401/403 "访问被拒绝" | 仅加了 `SecurityConfig` 白名单，`ViewConfig` 的 `IpRateLimitInterceptor` 仍拦截 `/api/**` | 两处白名单都要加：`SecurityConfig` `permitAll` + `ViewConfig` `excludePathPatterns`（缺一不可），重新打包 web |

**现象**：知识脉络图页面空白，`/api/v1/graph/stats` 返回 `entityCount: 0`

## 6. 安全相关

### 6.1 JWT 启动失败（弱密钥）

**现象**：chat-web / chat-core 启动即退出，日志报 `IllegalStateException: JWT secret 过短...`

**原因**：2026-08 新增弱密钥校验，`jwt.secret` 少于 32 字节拒绝启动。

**修复**：
```bash
# 生成强密钥并更新 .env
openssl rand -base64 48
# 编辑 /opt/app/.env 更新 JWT_SECRET，然后重启
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-all.sh"
```
> 当前生产 `JWT_SECRET` 长度 40 字节，符合要求。修改密钥后所有已登录用户需重新登录。

### 6.2 接口返回 429（限流命中）

**现象**：接口返回 `429 Too Many Requests` + `retry_after`

**可能原因**：
| 场景 | 阈值 | 位置 |
|------|------|------|
| 全局 IP 限流 | 同 IP 短时间大量请求 | `IpRateLimitInterceptor` |
| SQL 执行台 | 连续登录失败 ≥ 5 次 → 锁 15 分钟；每分钟执行 ≥ 30 次 | `SqlExecutorController` |
| 媒体生成 | 用户级生成频率超限 | `MediaGenController` + `RateLimitService` |

**处理**：等待窗口期结束（429 响应头带 `retry_after` 秒数），或检查是否有异常刷接口的脚本/客户端。

## 8. Multi-Agent 工作流排查（2026-08 新增）

### 8.1 请求未触发拆解（走了普通流程）

超长请求未并行可能有三个原因，按序排查：

```bash
# 1. 确认拆解判定：简单问题（长度 < min-length=120）不会拆解，属正常
# 2. 全局限流降级：并发过载时 core 日志会出现"并发过载降级"
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep '并发过载降级' /opt/app/logs/core-9090.log /opt/app/logs/core-9092.log | tail -20"
# 3. 检查全局计数是否泄漏（应为空或 0，不应 ≥8）
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "/usr/local/redis/bin/redis-cli -p 6379 get agent:workflow:active"
```

> 若 `agent:workflow:active` 长期 ≥ max-concurrent=8，说明有工作流许可未释放（异常泄漏）。工作流结束后许可会自动释放（RELEASE Lua 脚本下限为 0）；极端情况下可手动清理：`redis-cli del agent:workflow:active`。

### 8.2 子任务执行失败 / 结果丢失

```bash
# 查看子任务分发与完成情况（taskId 格式: {planId}-tN）
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -E '子任务已分发|任务完成|任务执行失败' /opt/app/logs/core-9090.log /opt/app/logs/core-9092.log | tail -50"
# 查看结果收集进度（received/total）
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "/usr/local/redis/bin/redis-cli -p 6379 --scan --pattern 'agent:plan:*:total'"
```

排查要点：
- **Worker 失败语义**：`SubAgentWorker` 执行失败会回传失败结果并 `basicNack(requeue=false)`（防无限重试重复计数），该子任务在收敛答案中标记"失败"，属预期行为而非丢失
- **Collector 失败语义**：`SubTaskResultCollector` 处理失败 `requeue=true`，Redis 操作幂等可安全重试
- **manual ack + prefetch=1**：Worker 忙时不拉新消息，子任务不会因实例重启丢失（requeue 自动重投）

### 8.3 收敛未完成 / 回答卡住（WorkflowReconciler 兜底）

正常路径由 `SubTaskResultCollector` 在 received ≥ total 时触发收敛；若收敛中途崩溃（JVM 退出/异常），重启后无新消息触发，plan 会卡住。**WorkflowReconciler 每 30s 扫描自动兜底**：

```bash
# 查看 Reconciler 是否发现并触发（应看到"结果已齐但未收敛完成，重新触发收敛"）
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -E 'Reconciler|收敛完成' /opt/app/logs/core-9090.log /opt/app/logs/core-9092.log | tail -30"
```

排查要点：
- Reconciler 触发条件：received ≥ total 且 DB 非 done 且无 `converged` 标记且锁可获取
- **去重依据**：`agent:plan:{id}:converged` 标记（主）+ DB 状态 done（兜底）；内部 API 请求可能无 DB 行，仅靠 DB 判断不可靠
- 若 plan 卡住且 Reconciler 未触发：检查 Redis `agent:plan:{id}:*` 键是否过期（TTL 30min）或 meta 缺失（`readMeta` 返回 null 会跳过并打 WARN）
- 手动触发收敛验证（紧急）：`redis-cli del agent:plan:{id}:converged` 后等待下一扫描周期

### 8.4 收敛锁卡住导致不触发

`agent:plan:{id}:lock` 由正常路径写入（TTL 2min）或 Reconciler 写入（TTL 5min），到期自动过期，一般不会卡死。若怀疑锁异常残留：

```bash
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "/usr/local/redis/bin/redis-cli -p 6379 ttl agent:plan:{planId}:lock"
# 返回 -2 表示锁已过期（正常），返回正数表示仍在持有
```
