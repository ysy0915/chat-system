## 二、安全扫描工具

### 2.1 工具矩阵

| 工具 | 运行时机 | 扫描对象 | 阻断？ | 配置 |
|------|---------|---------|:---:|------|
| **Checkstyle** | CI push | 代码风格 | ✅ 是 | `checkstyle.xml` |
| **PMD** | CI push | 代码质量 | ✅ 是 | `pmd-ruleset.xml` |
| **SpotBugs + FindSecBugs** | CI push | Java 缺陷+安全漏洞 | ⚠️ 不阻断 | `spotbugs-exclude.xml` |

### 2.2 Gitleaks 配置

**扫描规则** (`.gitleaks.toml`):
- 通用 API Key / Token / Secret 匹配
- JWT 签名密钥检测
- 数据库连接字符串密码检测
- PEM 私钥文件头检测
- GitLab Pipeline Token 检测

**白名单**:
- `docs/**/*.md` — 文档中的示例密钥
- `src/test/**` — 测试数据
- `frontend/.env.development` — 开发环境变量（不含真实密钥）
- `target/`, `node_modules/`, `.idea/` — 构建产物和 IDE 配置

### 2.3 OWASP Dependency-Check

**触发 CVSS 阈值**: ≥ 7.0 (高危和严重)

**抑制文件** (`owasp-suppressions.xml`):
- 审查确认不影响的 CVE 可添加抑制规则
- 每个规则必须标注审查人、日期、原因

**查看报告**:

## 三、运行时安全

### 3.1 JWT 鉴权

- **签名算法**: HMAC-SHA256
- **密钥长度**: ≥256 位（≥32 字节，**弱密钥拒绝启动**，用 `openssl rand -base64 48` 生成）
- **Token 有效期**: 访问令牌 24h，刷新令牌 7d
- **存储**: 前端 `httpOnly` cookie (不暴露给 JS)
- **吊销**: 无状态，不支持单点吊销（未来可用 Redis 黑名单）
- **DTO 校验**: 登录/注册接口 `@Valid` + `@Size` 统一参数校验

详见 [安全配置说明.md](安全配置说明.md)

### 3.2 接口白名单

所有公开接口需要显式在白名单中配置，当前清单见 `SecurityConfig.java`:

```
GET    /api/v1/public/**
GET    /actuator/health
POST   /api/v1/auth/login
POST   /api/v1/auth/register
WS     /ws/**
```

### 3.3 IP 限流

`IpRateLimitInterceptor` 基于 Redis 漏桶算法（2026-08 起扩展为三层业务级限流，见 [安全配置说明.md](安全配置说明.md) 第四章）:
- **全局**: 100 req/min per IP
- **登录**: 5 req/min per IP
- **注册**: 3 req/min per IP

### 3.4 内容安全（两道防线）

统一抽象为契约接口 `ContentSafetyProvider`，按「通用闸门」与「大模型自检」分两层落地：

**第一道防线（chat-common 通用闸门）** — `ContentSafetyService` 对接阿里云内容安全 API + 本地敏感词库：
- 敏感词过滤（政治、色情、暴力等），本地词库微秒级预检命中即拦截
- 输入检查: 用户提问（chat-web 发送前）
- 输出检查: LLM 生成内容（chat-core 完整答案后）
- 违规处理: 返回安全提示，记录审计日志
- 异常策略: **fail-close**（本地未命中但阿里云不可用时拒绝放行，防绕过）

**第二道防线（chat-llm 大模型自检）** — `LlmContentSafetyService` 内聚大模型可插拔模块的 native guardrail：
- SPI: `GuardrailProvider`（`name`/`isAvailable`/`check`），聚合器实现同一 `ContentSafetyProvider` 契约
- gRPC 暴露: `LlmSafety.Check`，供 web/core 叠加调用
- 语义: 增量自检（可用即检、不可用放行，由第一道防线兜底），本期搭框架 `NoopGuardrailProvider` 占位

### 3.5 Nginx 安全响应头

```nginx
X-Content-Type-Options: nosniff         # 防 MIME 嗅探
X-Frame-Options: DENY                   # 防 Clickjacking
X-XSS-Protection: 1; mode=block         # 防 XSS
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: default-src 'self'; ...   # CSP 内容安全策略
Permissions-Policy: camera=(), microphone=(), geolocation=()
server_tokens: off                      # 隐藏 Nginx 版本
```

> HSTS 暂未启用（需先全站 HTTPS）

## 四、秘钥管理

### 4.1 秘钥分类

| 密钥类型 | 存储位置 | 访问控制 |
|---------|---------|---------|
| JWT 签名密钥 | 环境变量 `JWT_SECRET` | 仅应用服务器 |
| 数据库密码 | 环境变量 `DB_PASSWORD` | 仅应用服务器 |
| LLM API Key | Nacos 配置中心 | Nacos ACL |
| 阿里云 AK/SK | 环境变量 / Nacos | 最小权限 RAM 角色 |
| SSH 私钥 | 开发者本地 `~/Downloads/` | 仅开发者 |
| GitHub Secrets | GitHub Actions Secrets | 仅仓库管理员 |

### 4.2 禁止事项

- ❌ 密钥硬编码在代码中
- ❌ 密钥提交到 Git 仓库
- ❌ 密钥通过即时通讯工具传输
- ❌ CI 日志中输出密钥
- ❌ 所有环境共用同一密钥

### 4.3 泄露应急

如果怀疑密钥泄露:
1. **立即轮换** — 生成新密钥，更新所有引用
2. **审计日志** — 检查是否被滥用（API 调用量突变）
3. **Git 清理** — 如有 commit 使用 `git filter-branch` 或 `BFG Repo-Cleaner` 清除历史
4. **更新 Secrets** — GitHub Secrets 和服务器 `.env` 同步更新

## 五、合规检查清单

### 5.1 每次发布前

- [ ] Gitleaks 扫描通过（无新增密钥泄露）
- [ ] OWASP Dep-Check 无高危 CVE
- [ ] SpotBugs + FindSecBugs 无新增 security 级别问题
- [ ] 接口白名单无意外放开的路径
- [ ] actuator 仅暴露 health, metrics, prometheus 端点
- [ ] Nginx 安全响应头配置正确（含 CSP）
- [ ] CORS 配置仅允许预期 Origin
- [ ] 管理密码已通过 env 注入（无硬编码默认值）

### 5.2 每季度

- [ ] 依赖版本更新（Spring Boot / Spring Cloud 等）
- [ ] CVE 数据库同步 + 历史抑制规则复审
- [ ] 用户权限审计
- [ ] API Key 轮换
- [ ] 渗透测试（内部）

## 六、已知风险与缓解

| 风险 | 严重度 | 缓解措施 | 状态 |
|------|:---:|------|:---:|
| LLM Prompt 注入 | 中 | 内容安全过滤 + 角色限定 | 已部署 |
| WebSocket 无鉴权 | 中 | JWT 握手验证 + Token 过期驱逐 | 已部署 |
| actuator 信息泄露 | 低 | 仅暴露 health+metrics+prometheus 端点，不暴露 details | 已部署 |
| IP 限流可绕过 (X-Forwarded-For 伪造) | 低 | Nginx 设置 X-Real-IP，取第一个有效 IP | 已部署 |
| 静态资源无版本哈希 | 低 | Vite 构建自带 content hash | 已部署 |
| Docker 镜像以 root 运行 | 中 | Dockerfile 已切换为非 root | 已部署 |
| JWT 弱密钥 | 中 | 启动时校验 ≥32 字节，弱密钥拒绝启动 | ✅ 已修复 (2026-08) |
| SQL 执行台滥用 | 中 | 登录失败锁定 15 分钟 + 频率限流 + 危险关键字拦截 | ✅ 已修复 (2026-08) |
| 媒体生成刷接口 | 中 | 用户级限流 (429 + retry_after) | ✅ 已修复 (2026-08) |
| 超大文件上传 | 中 | 全模块统一 10MB 限制 | ✅ 已修复 (2026-08) |
| Neo4j 启动竞态 | 中 | 60s 守护线程自动重连 | ✅ 已修复 (2026-08) |
| CORS 跨域未显式配置 | 低 | SecurityConfig 显式 CORS + OriginPattern 白名单 | ✅ 已修复 (2026-08) |
| 代码硬编码默认密码 | 中 | AdminAuthUtil 清空默认值，必须通过 env 注入 | ✅ 已修复 (2026-08) |
| 无方法级权限控制 | 低 | @EnableMethodSecurity + @PreAuthorize 注解支持 | ✅ 已启用 (2026-08) |
| Mockito/ByteBuddy 版本不兼容 JDK 26 | 低 | 升级 Mockito 5.14.2 + ByteBuddy 1.15.11 | ✅ 已修复 (2026-08) |
| 缺失 import 导致 JDK 26 编译失败 | 低 | 批量补充显式 import | ✅ 已修复 (2026-08) |
