# 代码规范与质量说明

> 代码质量工具配置、使用指南、检查维度

---

## 一、代码质量体系总览

```
git push / CI 触发
    │
    ▼
├─ validate 阶段
│   ├─ checkstyle:check  → 代码风格检查 (checkstyle.xml)
│   └─ pmd:check         → 静态分析 (pmd-ruleset.xml)
│
├─ test 阶段
│   ├─ surefire:test     → 单元测试
│   ├─ jacoco:report     → 覆盖率报告
│   └─ spotbugs:check    → Bug 检测 (FindSecBugs)
│
└─ verify 阶段 (CI only)
    ├─ jacoco:check      → 覆盖率阈值
    ├─ spotbugs:check    → 强制 SpotBugs
    ├─ checkstyle:check  → 强制 Checkstyle
    └─ pmd:check         → 强制 PMD
```

## 二、工具配置

### 2.1 Checkstyle — 代码风格

**配置**: `checkstyle.xml`（Google Java Style 定制版）

| 检查维度 | 说明 |
|---------|------|
| 命名规范 | 包名/类名/方法名/常量/局部变量 |
| Import 规范 | 禁止 `*` 通配符导入、未使用的 import |
| 空白与格式 | 缩进、换行、括号、空格 |
| 代码块 | 空 catch 块警告、必须有大括号 |
| 编码实践 | 隐藏字段、魔法数字、内联赋值 |
| Javadoc | public 方法需要文档（宽松策略） |

**使用**:
```bash
# 生成报告（不阻断）
mvn checkstyle:check

# 查看报告
open target/checkstyle-result.xml
```

### 2.2 PMD — 静态分析

**配置**: `pmd-ruleset.xml`（4 大类规则集）

| 规则集 | 说明 |
|-------|------|
| `bestpractices` | 最佳实践：避免 System.out、简化表达式 |
| `codestyle` | 代码风格：短变量名、不需要的修饰符 |
| `design` | 设计：圈复杂度 ≤15、耦合度 |
| `errorprone` | 易错：避免空 catch、避免 NPE 捕获 |
| `multithreading` | 多线程：同步问题 |
| `performance` | 性能：不必要的包装、字符串拼接 |

**使用**:
```bash
# 生成报告（不阻断）
mvn pmd:check

# 查看报告
open target/pmd.xml

# 查看 HTML 报告
mvn pmd:pmd
open target/site/pmd.html
```

### 2.3 SpotBugs + FindSecBugs

**配置**: `pom.xml` 内置 + `spotbugs-exclude.xml` 排除规则

| 维度 | 说明 |
|------|------|
| effort | Max |
| threshold | Medium |
| 安全扫描 | FindSecBugs 1.13.0（SQL注入、XSS、路径遍历等） |

**使用**:
```bash
# 生成报告
mvn spotbugs:check

# 查看报告
open target/spotbugsXml.xml
```

## 三、代码规范要点

### 3.1 必须遵守

- ❌ 禁止 `System.out.println` — 使用 `log.info/debug/error`
- ❌ 禁止 `import java.util.*` — 使用具体 import
- ❌ 禁止空的 catch 块 — 至少记 `log.warn` 或加注释说明
- ✅ Entity 字段用 `private` + getter/setter（或 Lombok `@Data`）
- ✅ `catch (Exception)` 只在兜底层使用，业务层捕获具体异常
- ✅ 方法行数 ≤ 80 行，参数 ≤ 8 个
- ✅ 使用完 JDK 标准库类后确保 `import` 显式声明（如 `java.util.Locale`, `java.util.HashMap`）

### 3.2 建议遵守

- public 方法/类加 Javadoc
- 魔法数字提取为常量（`-1, 0, 1, 2, 3, 4, 5, 10, 60, 100, 1000` 可豁免）
- Redis Key 前缀集中管理到常量类
- 测试需要有实际业务断言，不要只检查 `Class.forName`

### 3.3 构建模式

| 模式 | 命令 | Checkstyle/PMD | SpotBugs |
|------|------|:---:|:---:|
| 本地 | `mvn clean install` | 报告不阻断 | 报告不阻断 |
| CI | `mvn clean verify -Pci` | **强制阻断** | **强制阻断** |

## 四、存量问题处理策略

当前 PMD 存量违规已从最初的 2000+ 条收敛至 **92 条**（均为短变量名、方法参数未声明 final 等风格类问题，非缺陷类）；Checkstyle 已 **0 违规**。与根 README「PMD 2000+→92」口径一致。

**策略**：
1. 本地构建 `failOnError=false` — 生成报告不阻断
2. CI Profile `failOnViolation=true` — 但增量阶段暂不打开 CI 的 Checkstyle/PMD 强制阻断（`-Pci` 暂不启用即可）
3. 新功能代码必须通过所有检查
4. 存量问题逐步清理（92 条风格类，属时间成本非架构缺陷）

## 五、一键检查命令

```bash
# 全部代码质量检查
mvn clean verify -Pci

# 单独运行某项
mvn checkstyle:check                     # 代码风格
mvn pmd:check                            # 静态分析
mvn spotbugs:check                       # Bug 检测
mvn jacoco:report                        # 覆盖率报告

# 查看汇总报告
mvn site                                 # 生成完整站点报告
```
