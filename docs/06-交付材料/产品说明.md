>
> 制作者：杨思义 · 博思AI团队 · 2026年8月

## 一、产品简介

博思AI智能体是一个**多模型智能协作平台**。不同于传统 AI 产品"一个模型回答一个问题"的单声道模式，博思AI 让**豆包、DeepSeek、千问**等多个大模型同时参与对话、展开辩论、协作完成复杂任务，并融合 RAG 知识检索、多模态生成、AI 游戏于一体，提供一站式 AI 体验。

**在线体验**：http://112.124.106.108/chat/home
**源码仓库**：https://github.com/ysy0915/chat-system

---

## 二、核心理念

> 不只一个 AI 回答你，而是一群 AI 一起帮你。

| 传统 AI 产品 | 博思AI智能体 |
|---|---|
| 单一模型回答 | 多模型群聊 + 多模型随机组队辩论 |
| 黑盒推理 | 思考链实时透明展示 |
| 所有问题同一参数 | 意图三层漏斗分级处理 |
| 聊天/绘画/视频分散在不同 App | 聊天、辩论、创作、游戏统一入口 |
| 模型报错就卡住 | 自动换模型/重试/降级，服务不中断 |

## 三、功能全景

### 3.1 AI 伙伴群聊
多个 AI 模型同时参与公开聊天室，用户可切换 AI 回答模式，支持流式输出、在线人数实时显示、跨用户问答可见。

### 3.2 个人对话空间
JWT 认证的私密一对一 AI 对话，历史记录持久化，支持文件上传（txt/csv/json/图片等）、语音输入、语音朗读、历史搜索、模型切换、重新生成、停止生成。知识/事实类问题自动触发 RAG 检索增强。

### 3.3 观点辩论场
**两种辩论模式**：
- **标准辩论**：从已配置 chat 模型随机抽取 **3~6 个模型组队**（模型数可自选，名称中文展示），场次可选 1~10 轮（默认 3 轮），每轮反思修正，最终裁决式汇总
- **树状辩论**：LLM 自动拆解问题为 2-3 个分析视角 → 各视角由 3 个快模型独立并行辩论（排除本地慢模型提速）→ 综合汇总，前端可拖拽 DAG 树图可视化展示论证网络

### 3.4 情绪树洞
匿名情绪倾诉空间，AI 共情回复。具备 **Memory 记忆增强**：LLM 提炼用户画像（情景/情绪/偏好），回答逐步贴合个人偏好。三层记忆架构：Redis 短期（最近 5 轮）→ Milvus 长期（向量检索）→ 用户画像。

### 3.5 多模态生成
- **文生图**：自然语言描述生成图片
- **文生视频**：文字描述生成短视频
- **图生 3D 模型**：图片转 GLB/OBJ/STL 三维模型

### 3.6 AI 多人游戏
- **城堡围攻**：AI 领主积分 + 兵力招募 + 实时对战
- **蛇王争霸**：多人贪吃蛇竞技
- **AI 乒乓球**：与 AI 对战

三种游戏的界面及动态文本（击杀 / 复活 / 道具 / 排行榜等）均支持中英文切换。

### 3.7 知识库 RAG
用户上传 PDF/Word/TXT 文档 → 自动解析分块 → Milvus 向量存储 → 对话时意图驱动自动检索增强回答。支持知识库管理、文档列表、删除等操作。

### 3.8 知识脉络图
Neo4j 图数据库存储实体与关系，LLM 自动抽取三元组，前端 Canvas 可视化展示知识网络。

### 3.9 Multi-Agent 并行工作流
超长/跨域复杂请求自动拆解为最多 9 个子任务 → RabbitMQ 分发到双实例 10 并发 Worker 并行执行 → 收敛压缩为 ≤1000 字结构化输出。具备全局限流、公平分发、死信重试、对账兜底的可靠性闭环。

### 3.10 多语言（i18n）
全站一键中英文切换：首页、聊天、辩论、树洞、私聊、管理后台、游戏等全部页面文案全面翻译（translations.js 600+ 词条，zh/en 完全对称）。游戏动态文本（击杀 / 复活 / 道具 / 排行榜）、语音提示、在线状态同步翻译。切换入口：桌面端顶部导航栏（首页横条已移除），移动端公告喇叭左侧。

## 五、核心创新点

### 5.1 意图识别三层漏斗
按命中概率分配计算资源，避免所有问题都走 LLM 深度链路：
- **L1 规则匹配**（0-1ms）：Trie 树关键词，40 条规则
- **L2 语义匹配**（30-80ms）：Milvus k-NN，~420 条种子示例
- **L3 LLM 分类**（200-1000ms）：兜底，高置信结果自动灌回 L1/L2（自增强闭环）
- L1+L2 命中率目标 >95%，意图驱动 Temperature 自动调参（代码 0.2 / 创意 0.95 / 翻译 0.1）

### 5.2 树状辩论 — Plan-and-Execute + LangGraph 混合编排
- **Plan**：LLM 拆解问题为多个分析视角
- **Execute**：Java CompletableFuture 视角间并行 + LangGraph4j StateGraph 视角内循环辩论
- **Aggregate**：LLM 综合汇总形成最终结论
- 容错设计：单视角失败不影响其他，汇总失败自动本地拼接

### 5.3 思考链实时展示
三态状态机逐 token 分离推理过程，11 字符缓冲零延迟推送，300 字符安全降级。仅实时展示不存库，保持历史记录干净。

### 5.4 AI 错误自愈
| 错误类型 | 自愈策略 |
|---------|---------|
| 频率限制/超时 | 换同 Provider 其他模型重试 |
| 认证失败 | 跳过失败模型，用默认模型 |
| 网络错误 | 等待 1s 重试 |
| 解析错误 | 降 temperature 到 0.3 重试 |
叠加 Resilience4j 熔断器（50% 失败率 → 30s 熔断）形成双层防御。

### 5.5 Multi-Agent 并行工作流
复杂任务自动拆解 → 并行执行 → 收敛压缩，具备四重可靠性保障：
- Redis Lua 原子限流（8 并行 / 超限降级，不排队不拒绝）
- manual ack + prefetch=1 公平分发，子任务零丢失
- DLX 死信指数退避重试（1s→2s→4s→60s，最多 5 次）
- Reconciler 30s 对账兜底，服务器重启后自动恢复收敛

### 5.6 对话自动 RAG
知识/事实类问题自动检索知识库增强回答，**可查性三层判定**（开关 → 意图 → 排除实时/个人数据），避免无效 Embedding 检索。未命中/失败自动降级普通回答。

## 六、安全与合规

### 6.1 内容安全
接入阿里云内容安全 API，色情/暴力/政治敏感/违禁内容自动拦截。

### 6.2 安全防护
| 策略 | 说明 |
|------|------|
| IP 限流 | 600 次/分钟 |
| 用户限流 | 20 次/分钟、200 次/小时 |
| 敏感接口限流 | 登录/注册 10 次/分钟 |
| 登录防爆破 | 连续 5 次失败锁定 15 分钟 |
| 注册验证码 | 算术题验证码，5 分钟有效一次性消费 |
| 自动拉黑 | 60 秒超 1000 次 → 封禁 10 分钟 |
| UA 过滤 | 拦截 curl/wget/scrapy 爬虫 |
| CORS + CSP | 白名单域名 + 防 XSS |
| SSH 加固 | 仅密钥登录，禁用密码 |

### 6.3 数据隐私
- JWT 认证 + 用户级会话隔离
- 个人对话内容不跨用户共享
- 思考链仅实时展示不持久化
- 知识库文档按用户空间隔离

## 九、使用指南

### 在线访问
- 前端：http://112.124.106.108/chat/
- API：`/api/v1/*`
- WebSocket：`/ws/chat`

### 核心操作
1. **注册/登录**：首页点击注册，填写算术验证码即可创建账号
2. **群聊**：进入"AI伙伴群聊"，多个 AI 模型可同时回答你的问题
3. **个人对话**：进入"个人对话空间"，享受私密 AI 对话，可上传文件、语音输入
4. **辩论**：进入"观点辩论场"，输入争议性话题，选择标准/树状辩论模式
5. **树洞**：进入"情绪树洞"，匿名倾诉，AI 会记住你的偏好
6. **创作**：进入"图片与视频"或"3D模型生成"，用文字描述生成多模态内容
7. **知识库**：进入"知识库"，上传文档后对话时自动 RAG 增强

### 本机部署
```bash
# 1. 打包后端
mvn clean install -DskipTests

# 2. 启动 chat-llm（LLM 独立服务）
java -jar chat-llm/target/chat-llm-0.0.1-SNAPSHOT.jar --spring.profiles.active=local --server.port=9095

# 3. 启动 chat-core（核心 AI 服务）
java -jar chat-core/target/chat-core-0.0.1-SNAPSHOT.jar --spring.profiles.active=local --server.port=9090

# 4. 启动 chat-web（Web 接入层）
java -jar chat-web/target/chat-web-0.0.1-SNAPSHOT.jar --spring.profiles.active=local --server.port=8080 --app.core.base-url=http://127.0.0.1:9090

# 5. 启动前端
cd frontend && npm install && npm run dev
```
访问 http://localhost:5173
