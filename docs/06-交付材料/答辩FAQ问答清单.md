## 一、技术深度类（评委验证「你是不是真懂」）

### Q1：你的 Multi-Agent 并行工作流，和直接调一个 LLM 有什么区别？

**直接答案**：核心区别有两个——「并行」和「可靠」。

**展开要点**：
- 单个 LLM 串行处理长任务，受上下文窗口限制，且慢；我把请求拆成 ≤9 个子任务并行执行，收敛后压缩到 1000 字以内，速度和容量都提升。
- 更关键的是**可靠性**：并行意味着「部分失败」是常态，我做了 MANUAL ack + DLX 死信重试 + Reconciler 对账三层保障，这是单纯「调一个 LLM」完全不需要考虑的问题。

### Q2：为什么用 MANUAL ack，而不是 RabbitMQ 默认的 auto ack？

**直接答案**：为了保证「结果零丢失」。

**展开要点**：
- auto ack 是消息一被取走就确认，如果 Worker 处理到一半挂了，结果就丢了，而收敛逻辑会永远等不到这个子任务的结果。
- 我改成 MANUAL ack，在**结果成功落库之后**才 ack。处理失败就走 NACK 进死信队列，指数退避重试。

### Q3：你的「对账器（Reconciler）」是干嘛的？为什么需要它？

**直接答案**：兜底服务器崩溃后的任务恢复。

**展开要点**：
- 如果 core 服务在处理工作流的过程中整机宕机，Redis 里的 plan 状态还在，但没进程去收敛了。
- Reconciler 每 30 秒扫描一次未完成的 plan（用 ZSet 索引，不是全量扫描），发现「应该收敛但没人收敛」的，就重新触发收敛。这样重启后能自愈。

### Q4：意图三层漏斗，怎么保证 L1/L2 的准确率？

**直接答案**：L3 高置信结果自动反哺 L1/L2，形成自增强闭环。

**展开要点**：
- L1 是精确规则（正则/关键词），0-1ms，绝对准确但覆盖窄。
- L2 是语义匹配（向量/编辑距离），30-80ms。
- L3 是 LLM 兜底。当 L3 给出高置信度的意图判断时，会把「这个问题的意图」写回规则库，下次同类问题直接 L1 命中。所以准确率是「越用越高」的。

## 二、原创性与 AI 使用类（最敏感，必须答得坦诚）

### Q5：这个项目是不是用 AI 生成的？

**直接答案**：我用了 AI 辅助编码，但架构设计和核心方案是我独立完成的。

**展开要点**（重点，别慌）：
- 我诚实地披露了：AI 用于提高编码效率（样板代码、工具函数）。
- 但 25 条 ADR 架构决策记录、Multi-Agent 可靠性方案、意图漏斗设计，这些**「为什么这么设计」的判断**是我独立完成并反复验证的。
- 证据：我有一份《项目原创性与技术贡献说明》文档，明确划了 AI 辅助和独立原创的边界。

### Q6：你的架构决策记录（ADR）是真的吗？还是事后补的？

**直接答案**：是真实的，但部分是在迭代过程中逐步沉淀的，不是一次性写的。

**展开要点**：
- 25 条 ADR 对应了真实的迭代过程（从 7 月底立项到 8 月中旬上线）。
- 每条 ADR 都有「背景→决策→后果」，比如「nodeId 固定 node-{port}」这条，是因为真实遇到过 RabbitMQ 队列堆积的问题才做的决策。

## 三、价值与差异化类（评委验证「你凭什么是你」）

### Q7：现在市面上已经有很多多模型/Agent 产品了，你的差异化在哪？

**直接答案**：我的核心差异化是「多模型**辩论**」+「**可靠性工程**」两个点。

**展开要点**：
- 大多数产品是「多模型并列输出」，我是「多模型**对抗式辩论**」——有正反方、有反思修正、有裁决，这是解决「单一模型偏见」的独特场景。
- 另一个差异化是可靠性闭环（手动 ack + 死信重试 + 对账），大多数 demo 级项目不会做这个。

### Q8：你的商业价值是什么？怎么赚钱？

**直接答案**：短期是「决策辅助工具」，长期是「多模型协作的通用能力」。

**展开要点**：
- 直接价值：内容创作（辩论式观点生成）、决策支持（多视角分析）。
- 可复用价值：chat-llm 模块可以独立部署成通用 LLM 网关，这是一个可单独产品化的能力。
- 诚实说明：目前是开源项目，商业化的路径在探索中，但技术能力是可复用的。

### Q9：你这个项目，用户真的有需求吗？谁来用？

**直接答案**：需求来自「单一答案不可信」这个真实痛点。

**展开要点**：
- 场景举例：重要决策前（职业选择、投资判断、产品方案评审），用户希望听到多方声音而不是一个模型的「自信但可能错误」的回答。
- 目标用户：需要多视角决策的普通用户、内容创作者、做方案评审的团队。

## 附：答辩临场技巧

1. **先结论后展开**：每个问题都先给「一句话直接答案」，再展开，评委时间宝贵。
2. **被问倒不要硬编**：如果真不会，诚实说「这个我还没深入到这个细节」，比编造强。
3. **主动引导到 demo**：技术问题答完，主动说「这个在 demo 里可以现场演示」，把评委注意力引到你最强的「可运行」上。
4. **准备一个「杀手锏演示」**：如果评委问「最能体现你技术的一个点是什么」，直接现场演示「辩论场」或「Multi-Agent 拆分」，这比任何语言都有说服力。
