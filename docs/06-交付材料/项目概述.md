## 一、目标用户

| 用户群体 | 典型场景 | 核心需求 |
|----------|---------|---------|
| **普通用户** | 日常对话、知识问答、情绪倾诉 | 需要一个能聊得来、有温度、不敷衍的 AI 伙伴 |
| **深度思考者** | 复杂问题决策、观点辩论、多角度分析 | 想要多个 AI 从不同立场展开辩论，帮助看清问题全貌 |
| **内容创作者** | 配图生成、短视频制作、3D 模型产出 | 用自然语言描述就能生成图片/视频/3D 素材，降低创作门槛 |
| **开发者 / 学习者** | 代码生成、文档检索、知识问答 | 需要 AI 理解技术上下文，结合文档知识库给出精准答案（知识/事实类问题自动触发 RAG 增强） |
| **游戏玩家** | 与 AI 对战或协作的休闲游戏 | 在聊天应用中体验 AI 驱动的多人对战，社交 + 娱乐一体 |

## 二、核心用户诉求 

用户在使用现有 AI 产品时面临 8 个根本性问题：

1. **单一模型偏见**：一个模型一种观点，用户只能听到单方说辞，无法获得多元视角
2. **黑盒推理**：AI 给出答案但不展示思考过程，用户无法判断结论是否可靠
3. **意图识别粗暴**：所有问题用同一套参数处理，简单对话和复杂推理混为一谈，响应慢、体验差
4. **能力孤岛**：聊天、绘画、视频、游戏分散在不同平台，切换成本高，数据不互通
5. **稳定性焦虑**：LLM 调用经常报错、超时，用户被晾着等，没有自愈机制
6. **安全与体验矛盾**：不防刷被滥用，防太死影响正常使用，缺乏智能化的安全策略
7. **记忆缺失**：AI 记不住用户偏好与情绪状态，每次倾诉都要重新说明背景，回复缺乏个性化

## 三、解决方案

博思AI 是一个**多模型智能协作平台**，核心理念是「不只一个 AI 回答你，而是一群 AI 一起帮你」。

```
                            ┌──────────────┐
                            │   前端 SPA    │
                            │  React + Vite │
                            └──────┬───────┘
                                   │ HTTP / WebSocket
                            ┌──────▼───────┐
                            │   chat-web   │  网关层
                            │  限流·认证·路由 │
                            └──────┬───────┘
                                   │ Nacos 服务发现
         ┌───────────────┬─────────┼─────────┬──────────────┐
         ▼               ▼         ▼         ▼              ▼
   ┌──────────┐   ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
   │ chat-core│   │chat-games │ │chat-media│ │ chat-llm │ │  Milvus  │
   │ AI 核心   │   │ 多人游戏  │ │ 多模态   │ │ LLM 服务 │ │  知识库  │
   └──────────┘   └──────────┘ └──────────┘ └──────────┘
         │
    ┌────┴────┬──────────┬──────────┐
    ▼         ▼          ▼          ▼
  豆包    DeepSeek     千问     其他模型
```

**六大支柱能力**：

| 支柱 | 解决什么 | 如何做到 |
|------|---------|---------|
| **多方辩论** | 单一模型偏见 | 标准辩论 (三方交锋，场次可选 1~10 轮，默认 3) + 树状辩论 (LLM 拆解视角 → 并行辩论 → 汇总) |
| **意图漏斗** | 粗暴参数匹配 | L1 规则 (0-1ms) → L2 语义 (30-80ms) → L3 LLM 分类，按意图自动调参 |
| **思考链** | 黑盒推理 | ThinkingStreamParser 状态机实时剥离推理过程，仅展示不存库 |
| **记忆增强** | 记忆缺失 | 三层记忆（Redis 短期 + Milvus 长期向量 + 用户画像），树洞回答逐步贴合个人偏好 |
| **自动 RAG** | 知识库用不上 | 知识/事实类问题意图驱动自动检索知识库增强回答，可查性三层判定避免无效查询 |
| **全能力融合** | 能力孤岛 | 同一入口聊天 / 辩论 / 游戏 / 图片 / 视频 / 3D / 知识库，统一鉴权 |

## 四、创新点

### 1. 意图识别三层漏斗

```
请求 → L1 规则匹配 (0-1ms) → 命中? → 返回意图
              │ 未命中
              ▼
         L2 语义匹配 (30-80ms) → 置信度>0.7? → 返回意图
              │ 未命中
              ▼
         L3 LLM 分类 (200-1000ms) → 兜底返回 UNKNOWN
```

- 首创按命中概率分配计算资源的三级漏斗
- 规则热加载 + 自动挖掘（多级 TF-IDF 阈值 0.05/0.08/0.15 → LLM 标注意图）
- 意图驱动 Temperature：代码 0.2、创意 0.95、翻译 0.1，自动匹配
- 10 种意图全覆盖：40 条 L1 规则 + ~420 条 L2 种子示例
- **自增强闭环**：L3 高置信结果 → SeedPool → 自动灌入 L2 (Milvus) + L1 (Trie)
- **L2 动态阈值**：滑动窗口追踪每意图命中率，自动 ±0.02 调节
- L1+L2 综合命中率目标 >95%，仅 <10% 走 LLM 兜底

### 2. 树状辩论 — Plan-and-Execute + LangGraph 混合编排

```
Plan（规划）: 用户提问 → LLM 拆解为 2-3 个分析视角
                │
      ┌─────────┼─────────┐
      ▼         ▼         ▼
   视角A      视角B      视角C        ← Execute（执行）: Java 并行调度
      │         │         │
   ┌──┴─────────┴─────────┴──┐
   │  LangGraph StateGraph    │        ← 每视角内图式循环
   │  debate → reflect        │
   │  (反思) → shouldContinue │
   │    ↑           ↓         │
   │    └── (round < 3)       │
   │              (round≥3) → │
   │          summary → END   │
   └──────────────────────────┘
      │         │         │
   视角结论   视角结论   视角结论
      └─────────┼─────────┘
                ▼
   汇总（Aggregate）: LLM 综合汇总
```

- LangGraph4j `StateGraph` 做视角内循环编排，Java `CompletableFuture` 做视角间并行
- 整体为 **Plan-and-Execute 范式**：LLM 生成计划（拆解视角）→ Java/子图并行执行 → LLM 汇总
- 混合模式兼顾结构化编排和运行时灵活性（视角数量由 LLM 动态决定）
- 容错设计：单视角失败不影响其他视角，汇总 LLM 失败自动本地拼接

### 3. 思考链实时展示

- 三态状态机逐 token 分离 `<thinking>...</thinking>` 和普通内容
- 零延迟 emit：仅缓冲最后 11 字符用于模式匹配，其余即时推送
- 安全降级：300 字符无标签自动切非思考模式，避免误判
- 意图驱动触发：复杂意图自动开启，简单对话跳过
- 仅实时展示，不存入数据库，保持历史记录干净

### 4. AI 错误自愈

| 错误类型 | 自愈策略 |
|---------|---------|
| 频率限制 / 超时 | 换同 Provider 其他模型重试 |
| 认证失败 | 跳过失败模型，用默认模型重试 |
| 网络错误 | 等待 1s 后重试 |
| 解析错误 | 降 temperature 到 0.3 重试 |
| 模型不存在 | 不重试，直接报错 |

叠加 Resilience4j CircuitBreaker（50% 失败率 → 30s 熔断）形成双层防御。

### 5. 多层限流安全

```
IP 全局限流 600次/分钟
    └── 用户级限流 20次/分钟 / 200次/小时
            └── 敏感接口限流 10次/分钟
                    └── 自动拉黑 1000次/60s → 封禁 10min
```

加上 UA 爬虫过滤 + CORS 白名单 + CSP 防 XSS，Fail-open 容错（Redis 异常放行）。

### 6. 对话自动 RAG — 意图驱动的知识库增强

```
知识/事实类问题 (KNOWLEDGE_QA / TASK_EXECUTION)
  → shouldAutoRag 三层判定
  → RagClient.search(kbId, q, topK=3)
  → score ≥ 0.3 片段注入 system prompt → 增强回答
  → 知识库为空 / 未命中 / 失败 → 自动降级普通回答
```

- **可查性三层判定**：开关配置 → 意图判定 → 排除实时/个人数据查询（天气、时间、新闻、行情、比分、订单等），避免无效 Embedding 检索
- 个人对话与群聊全覆盖（群聊检索一次注入所有并发模型）；与 weather 等实时工具互补

### 7. 树洞 Memory 记忆增强 — 用户画像

```
每次倾诉 → LLM 提炼画像 (scene / emotions / preferences / context)
  → Redis user_profile:{scene}:{userId} (TTL 30 天)
  → 偏好增量合并 → 注入记忆上下文 → 回答贴合偏好
```

- 三层记忆架构：Redis 短期（最近 5 轮）→ Milvus 长期（向量检索 top-3）→ 用户画像（LLM 结构化提炼）
- 异步无侵入：画像提炼在 chat-llm 线程池执行，失败仅告警不影响保存主流程

### 8. AI 回答格式化清洗

- 前端 `stripMarkdownSymbols` 统一去除 `**` 等残留 Markdown 符号，所有 AI 回答输出干净文本
- 覆盖个人对话 / 群聊 / 树洞 / 思考链展示全场景

### 9. Multi-Agent 并行工作流 — 复杂任务拆解并行 + 可靠性闭环（2026-08-13）

```
超长/跨域请求 → TaskPlanner（意图判断 → LLM 拆解 ≤9 个子任务）
  → 子任务写 Redis meta + 入队 RabbitMQ（agent.task）
  → 双实例 SubAgentWorker ×10（prefetch=1 + manual ack）并行消费
  → 子结果写 Redis hash（幂等覆盖 + received 计数）
  → SubTaskResultCollector 轮询收敛 → LLM 汇总压缩 ≤1000 字 → DB done
```

- **Plan-and-Execute 规模化**：树状辩论视角级并行的升级版，把"拆解→并行→收敛"范式推广到任意复杂请求（业务报告 / 方案制定 / 跨域分析）
- **输出压缩**：收敛用轻量模型（qwen-turbo）汇总 + `converge-max-chars=1000` 硬截断，复杂任务回答从数千字收敛为 ≤1000 字结构化输出
- **全局过载保护**：`agent:workflow:active` Redis Lua 原子限流（双实例共享 `max-concurrent=8`），超限自动降级普通流程（不排队、不拒绝）；实测 100 并发 → 8 并行 + 92 降级，无雪崩
- **公平分发 + 零丢失**：manual ack + prefetch=1，Worker 忙时不拉消息按真实能力分发；成功 ack / 失败 nack(requeue=false) 防重复计数，子任务零丢失（T04 验证）
- **收敛对账兜底**：`WorkflowReconciler` 每 30s 扫描"结果已齐但收敛未完成"的 plan 重新触发收敛；converged 标记 + DB 状态 + SETNX 锁三层去重，服务器重启 / Worker 崩溃后自动恢复（方案 A 端到端验证×2）
- 全链路测试套件 `scripts/test-multiagent-suite.sh`：**PASS=12 / FAIL=0**，快速回归 PASS=8 / FAIL=0
