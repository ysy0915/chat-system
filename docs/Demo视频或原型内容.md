## 二、关键交互流程

### 流程 1：个人对话空间 — 复杂问题推理

**场景**：用户询问一个需要多步推理的技术问题。

**输入**：
```
"帮我写一个 Spring Boot + WebSocket 的群聊接口，要求支持 JWT 认证和心跳检测。"
```

**交互步骤**：
1. 用户输入问题，点击发送
2. 前端显示「思考中…」状态
3. 系统意图识别判断为 `CODE_GENERATION`
4. 自动调用 KnowledgeSearch 工具检索项目内知识库
5. AI 输出 `<thinking>` 标签内的推理过程，前端以灰色斜体实时展示
6. 最终代码以 Markdown 代码块形式输出，附带关键注释
7. 用户点击「重新生成」或「停止生成」

**预期效果**：
- 推理过程可见，增强可信度
- 代码可用、结构清晰
- 工具调用链路透明

---

### 流程 2：观点辩论场 — 树状辩论

**场景**：用户面临一个争议性决策问题。

**输入**：
```
"现在是否适合买入英伟达股票？"
```

**交互步骤**：
1. 用户进入「观点辩论场」页面，选择「树状博弈」
2. 系统 LLM 自动拆解为多个视角，例如：
   - 视角 1：财务基本面分析
   - 视角 2：AI 行业景气度
   - 视角 3：估值与风险
3. 每个视角中，豆包（正方）、DeepSeek（反方）、千问（中立）进行 3 轮辩论
4. 前端 DAG 画布实时生成节点：根节点 → 视角节点 → 轮次论点卡片 → 视角总结 → 最终汇总
5. 用户可拖拽画布、缩放查看、点击节点查看完整论点
6. 所有视角完成后，LLM 生成「最终结论」，理由逐句换行展示

**预期效果**：
- 问题被结构化拆解
- 多模型多角度交锋
- 用户获得平衡客观的决策参考
- 可视化 DAG 提升信息可读性

---

### 流程 3：情绪树洞 — 情感支持

**场景**：用户情绪低落，需要倾诉。

**输入**：
```
"最近工作压力很大，感觉撑不下去了。"
```

**交互步骤**：
1. 用户进入「情绪树洞」页面
2. 系统意图识别判断为 `EMOTIONAL_SUPPORT`
3. AI 开启共情模式，输出温暖、非评判性的回应
4. 思考链展示 AI 如何理解用户情绪并选择回应策略
5. 用户可继续对话，AI 保持耐心倾听并适时建议寻求专业帮助

**预期效果**：
- 用户感到被理解和接纳
- 回应安全、积极
- 不涉及医疗建议，合规边界清晰

### 流程 4：AI 伙伴群聊 — 多模型讨论

**场景**：用户抛出一个开放性问题，想看不同 AI 的观点。

**输入**：
```
"大家觉得 AI 会取代程序员吗？"
```

**交互步骤**：
1. 用户进入「AI 伙伴群聊」页面
2. 多个 AI 模型（豆包、DeepSeek、千问）同时在线
3. 各模型轮流发言，展示不同立场
4. 用户可以 @ 指定模型追问
5. 对话历史按发言者分组展示

**预期效果**：
- 模拟圆桌讨论
- 观点多元、互动自然
- 降低用户获取多角度信息的成本

### 流程 5：多模态创作 — 文生图

**场景**：用户需要为文章配图。

**输入**：
```
"生成一张未来城市的插画，赛博朋克风格，夜晚霓虹灯。"
```

**交互步骤**：
1. 用户进入「图片与视频」页面，选择「文生图」

5. 生成完成后展示图片，支持下载

**预期效果**：
- 自然语言描述即可生成可用素材
- 生成结果风格符合提示词

**交互步骤**：

**预期效果**：

- 实时对战流畅
- 排行榜激励玩家参与

## 三、样例输入输出

### 样例 1：代码生成

**输入**：
```
"帮我写一个 JWT 工具类，包含生成 token 和解析 token 两个方法。"
```

**输出**：
```java
@Component
public class JwtUtil {
    @Value("${jwt.secret}")
    private String secret;

    @Value("${jwt.expiration:86400000}")
    private Long expiration;

    public String generateToken(Long userId) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + expiration);
        return Jwts.builder()
                .setSubject(String.valueOf(userId))
                .setIssuedAt(now)
                .setExpiration(expiry)
                .signWith(Keys.hmacShaKeyFor(secret.getBytes()), SignatureAlgorithm.HS256)
                .compact();
    }

    public Long parseToken(String token) {
        Claims claims = Jwts.parserBuilder()
                .setSigningKey(Keys.hmacShaKeyFor(secret.getBytes()))
                .build()
                .parseClaimsJws(token)
                .getBody();
        return Long.valueOf(claims.getSubject());
    }
}
```

### 样例 2：树状辩论

**输入**：
```
"远程办公是否应该成为常态？"
```

**拆解视角**：
- 视角 1：工作效率与协作
- 视角 2：员工生活质量
- 视角 3：企业成本与管理

**最终结论输出示例**：
```
**【最终结论】**
远程办公可以作为混合办公模式的重要组成部分，但不应一刀切地成为唯一常态。

**【理由】**
1. 工作效率方面：部分岗位远程办公效率更高，但创意型和协作密集型岗位面对面效果更佳。
2. 生活质量方面：远程办公减少了通勤压力，提升了工作生活平衡，但也可能导致社交孤立。
3. 成本管理方面：企业可节省办公场地成本，但需要投入更多数字化管理工具和安全防护。

**【建议】**
企业应根据岗位性质设计弹性混合办公制度，同时配套数字化协作工具和文化建设。
```
