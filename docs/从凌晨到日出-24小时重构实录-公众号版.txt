第一阶段：需求改造与功能完善


----------------------------------------------------------------
1. 观点辩论场：三个大模型各自为战

需求很明确：豆包调豆包，千问调千问，DeepSeek 调 DeepSeek，最后让千问整合结论，全程不出现智谱。

原来的代码硬编码了"找智谱作为汇总模型"的逻辑，辩论模型也是用优先级排序模糊取前 N 个。这意味着模型组合不可控，换个模型配置就可能把智谱拉进来。

修复方案是按 provider 精确匹配：三个辩论模型固定取 doubao / qwen / deepseek 的 chat 类型，整合模型固定取 qwen 的 chat 类型，加三级回退兜底。

反思：模型选择逻辑不应该硬编码在后端代码里。更好的做法是把"辩论模型组合"做成配置项存到数据库，运营可以动态调整，不用改代码重新发布。


----------------------------------------------------------------
2. 跨页面状态保持：让页面切换不丢状态

用户在辩论场发起辩论，切到个人对话空间看一下，再切回来——辩论状态全没了。TreeHole、PersonalChat、Chat 都有同样的问题。

根因是 React Router 切换路由时会卸载旧组件，所有 state、WebSocket 连接、定时器全部销毁。

方案是自研 KeepAliveRoute 组件，所有页面常驻 DOM，用 display:none/flex 切换显示。这样切换路由只是改变可见性，组件不卸载，状态全部保留。

这个改动后来引发了一系列连锁问题——手机端滚动失效、输入卡顿——都在后面解决了。


----------------------------------------------------------------
3. 情绪树洞样式对齐个人对话空间

树洞的输入框、消息列表、返回按钮都要和个人对话空间视觉一致。逐项对齐：水平 padding 从 32px 改为 24px，textarea 单行高度从 24px 改为 40px（与 input 等高），移动端 padding 从 16px 改为 10px，消息气泡 max-width 统一为 85%。

保留差异：树洞的粉紫色调和发送按钮颜色，这是品牌特色。

第二阶段：合规与安全


----------------------------------------------------------------
4. 内测版本公告弹窗

作为内部测试版本，只通过 IP 地址向受邀用户开放，没有正式 ICP 备案。需要向用户声明：仅供测试、不收集敏感信息、AI生成内容已标注、测试数据结束后清除。

方案是会话级弹窗：首次访问立即弹出，3 秒倒计时按钮"我已了解并同意"，必须点按钮才能关闭。用 sessionStorage 而非 localStorage——关闭浏览器后会话结束，再次访问重新弹窗。

导航栏增加公告入口，电脑版和手机版都显示。


----------------------------------------------------------------
5. AI 生成内容必须标注

合规要求所有 AI 生成内容标注"AI生成"标识。涉及 6 个文件、10 处位置：Chat、PersonalChat、TreeHole、Debate、MediaGen、History、KnowledgeGraph。

定义全局样式 .ai-generated-tag，灰色小标签，11px 字号，半透明背景。在每处 AI 回答的内容末尾追加。

反思：标识应该作为后端响应的一部分统一返回，而不是前端逐个页面手动加。后续可在 Message 实体里加 generatedByAI 字段。


----------------------------------------------------------------
6. SQL 执行器二次验证

SQL 执行器原来只有一道密码登录，登录后可以执行任意 SQL。写操作一旦误执行就是灾难。

方案是执行前弹窗二次确认，按 SQL 类型分级：读操作绿色标签点确认即可，写操作红色危险标签必须重新输入管理密码，未知类型黄色警告需确认。弹窗还显示 SQL 内容预览。


----------------------------------------------------------------
7. 敏感页面后台化与密码配置化

Monitor 页面（在线人数监控）原本和普通页面一样常驻 DOM。改为条件渲染：仅当 URL 是 /monitor 时才挂载，离开立即卸载，不显示在导航菜单中，访问需要密码登录。

Monitor 的登录密码原本硬编码在前端 JSX 里，任何查看浏览器源码的人都能看到。改为后端接口校验，密码从 application.yml 读取，支持环境变量覆盖。


----------------------------------------------------------------
8. 注册表单：昵称改为可选

注册时强制要求昵称影响转化率。改为用户名和密码必填，昵称可选——不填时后端自动用 username 作为默认值。


----------------------------------------------------------------
9. 防爬虫与接口保护

项目暴露在公网 IP 上，没有任何防护的话一个晚上就能被爬虫扫穿。基于 Redis 实现了五层防护：

  第一层：IP 全局限流，单 IP 每分钟最多 60 次请求
  第二层：敏感接口限流，登录/注册每分钟最多 5 次
  第三层：自动拉黑，60 秒内超 100 次请求自动拉黑 10 分钟
  第四层：UA 过滤，拦截 scrapy/curl/wget/python-requests 等爬虫工具
  第五层：管理员手动管控，提供 API 拉黑/解封 IP

容错策略：Redis 异常时 fail-open（放行），可用性优先于安全性。

第三阶段：最难的一个 Bug


----------------------------------------------------------------
10. 在线人数只增不减

Monitor 页面显示其他模块在线人数只增不减，切换页面后旧 page 计数不下降。

根因是竞态条件：切换页面时前端发两条 STOMP 消息——unregister（旧 page）+ register（新 page）。但 STOMP 消息是异步的，两条消息到达后端的顺序不保证。

如果 register 先到：registerUser 执行后 localSessions 更新为新 page，随后 unregister 到达时 localSessions.remove() 返回新 page（已被更新），从新 page 的 set 里移除自己——把刚注册的给删了。

更糟的是，如果 STOMP 连接未就绪，unregister 消息直接被跳过不发，旧 page 的 sessionId 永远留在 Redis set 里。

方案是三层修复：

  第一层：unregisterUser 优先用传入的 page 参数
          不信任 localSessions.remove() 的返回值

  第二层：registerUser 兜底扫描所有 page
          每次 register 时主动扫描所有已知 page
          把该 sessionId 从非当前 page 中移除
          即使 unregister 消息丢失，下次 register 也会自动清理

  第三层：前端串行发送
          确保 unregister 在 register 之前发送

反思：跨进程状态同步的竞态问题极易被忽略。最佳实践是核心清理逻辑做幂等、不依赖消息顺序、有兜底全量扫描机制。


----------------------------------------------------------------
11. 5 分钟无操作自动断开

WebSocket 连接是宝贵资源。用户打开页面后离开不关闭，连接会一直占用服务器资源。

方案是前端 + 后端双保险：

前端：监听 mousemove/keydown/click/scroll/touchstart 五种事件，5 分钟无操作主动断开 STOMP 连接，显示红色提示条。用户恢复操作时自动重连。

后端兜底：每次 register 时记录心跳时间到 Redis，定时任务每 60 秒扫描一次，超过 5 分钟无心跳的 session 自动清理。防止浏览器崩溃、手机杀进程等导致僵尸 session。

为什么需要双保险？因为前端不能保证 100% 执行清理逻辑。

第四阶段：移动端适配的暗坑


----------------------------------------------------------------
12. 手机端首页滚动失效

KeepAliveRoute 改造后，手机端首页无法上下滚动。排查了一个多小时。

根因：第一版 KeepAliveRoute 的外层 div 用 display: block。而 .app-layout 是 height: 100vh; overflow: hidden 的 flex 容器。这个 div 没有 flex: 1，没有限制高度，导致内部 .landing 的 flex: 1; overflow-y: auto 完全失效。

方案：把 KeepAliveRoute 的 div 改为 flex 容器，加 flex: 1; min-height: 0; overflow: hidden; flexDirection: column。

反思：flex 布局的滚动容器嵌套是前端最常见的坑。关键三要素缺一不可：
  ① 父容器固定高度 + overflow: hidden
  ② 中间层 flex: 1 + min-height: 0（这个最容易被忽略）
  ③ 滚动层 flex: 1 + overflow-y: auto


----------------------------------------------------------------
13. 汉堡菜单加文字

手机端右上角的汉堡按钮只有三条横线，不够直观。改为"三条横线 + 菜单"二字，降低用户认知成本。


----------------------------------------------------------------
14. 树洞返回按钮样式对齐

树洞登录后的返回首页按钮，手机端样式和个人对话空间完全对齐：白底圆角、8px 18px padding、13px 字号、hover 蓝色高亮。

第五阶段：输入卡顿攻坚战


----------------------------------------------------------------
15. 注册输入卡顿

手机端注册账号时，输入用户名很卡而且输入不进去。

根因：KeepAliveRoute 改造后，所有 17 个页面常驻 DOM。AuthModal 是 AppShell 的子组件，每次按键触发 setRegForm，导致整个 AppShell 重渲染，17 个页面组件全部参与 diff。

修复：AuthModal 用 React.memo 包裹，closeAuth/openAuth 用 useCallback 稳定引用。


----------------------------------------------------------------
16. 所有对话框英文输入卡顿

英文输入每次按键都触发 onChange，中文输入有组合期所以感觉不到——这就是"英文卡、中文不卡"的原因。

根因：KeepAliveRoute 的 children（页面组件 JSX）是在 AppShell 渲染时每次新建的。即使 AppShell 不重渲染，组件自身的 state 变化也会导致重渲染。如果组件树很深，开销就大。

修复方案是三管齐下：

  ① 把 ROUTES 数组提到模块顶层
     JSX 元素只创建一次，不再随 AppShell 渲染重建

  ② 抽取 KeepAliveShell 组件 + React.memo
     pathname 不变时跳过整个 shell 的渲染
     17 个页面组件完全不参与 diff

  ③ KeepAliveRoute 本身也用 React.memo
     自定义比较函数只比较 pathname 和 matchPath


----------------------------------------------------------------
17. 禁用输入框英文联想

移动端输入框的英文联想导致无法正常输入。

方案：在 main.jsx 用 MutationObserver 全局监听 DOM 变化，自动给所有 input 和 textarea 添加 autocomplete="off"、autocorrect="off"、autocapitalize="off"、spellcheck="false"。

一次性解决所有 10 个文件、20+ 个输入框的联想问题，不需要逐个修改 JSX 文件。

第七阶段：其他优化


----------------------------------------------------------------
20. 数据库变更兼容低版本 MySQL

需要给 model_configs 表加 model_type 字段，但生产 MySQL 版本低于 8.0.29，不支持 ADD COLUMN IF NOT EXISTS。

方案：用存储过程做幂等 DDL，通过 information_schema 检查列是否存在，不存在才 ALTER。数据用 ON DUPLICATE KEY UPDATE 实现 upsert，可重复执行。


----------------------------------------------------------------
21. 自动问答频率调整

AI伙伴群聊的"三个AI一个提问二个回答"功能，从每 30 秒执行一次改为每 1 小时执行一次。凌晨 1 点到 9 点不执行。


----------------------------------------------------------------
22. 删除不需要的页面

内测版本不需要展示制作人个人信息，删除 About.jsx 和 about.css，清理所有引用。代码越精简，维护成本越低。

总结


24 小时，22 项改动，74 个文件，+1614 行 / -41484 行。


核心经验：

  架构
    KeepAlive 适合中后台，但要注意 flex 嵌套滚动和重渲染性能
    公共逻辑必须抽取，重复代码是技术债的源头

  安全
    密码必须配置化，AI 内容必须标注
    敏感页面需二次验证 + 后台化
    多层防护才能覆盖各种攻击场景

  稳定性
    跨进程状态同步要做幂等 + 兜底全量扫描
    不依赖消息顺序
    前端 + 后端双保险，不信任任何一端

  移动端
    flex 滚动容器三要素缺一不可
    输入卡顿的根因是重渲染，React.memo 是利器
    输入法联想用 MutationObserver 全局禁用

  合规
    内测声明需会话级弹窗
    不收集敏感信息
    AI 生成内容必须标注

  重构
    能抽象的抽象，能优化的优化
    但保持功能不变，只做代码抽象和清理
    先保证可用，再追求优雅
