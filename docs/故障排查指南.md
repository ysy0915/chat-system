## 二、常见问题

### 2.1 前端页面加载失败 / 白屏

**可能原因**：
1. Nginx 静态资源未更新
2. 前端 dist 文件未上传或路径不对
3. 浏览器缓存旧版本 JS

**排查步骤**：
```bash
# 检查主服务器静态资源是否存在
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "ls -la /opt/app/static/chat/"

# 重新上传前端
cd /Users/apple/IdeaProjects/chat-system-project/frontend
npm run build
scp -r -i "/Users/apple/Downloads/我的密钥.pem" \
  dist/* root@112.124.106.108:/opt/app/static/chat/
```

### 2.2 请求返回 401

**可能原因**：
1. JWT Token 过期
2. 接口不在 SecurityConfig 白名单中
3. 前端 `localStorage.auth_token` 被清除

**排查步骤**：
```bash
# 查看 Nginx 日志确认哪些接口返回 401
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "tail -100 /var/log/nginx/access.log | grep ' 401 '"
```

**修复**：如接口应为公开访问，在 `SecurityConfig.java` 添加：
```java
.requestMatchers("/api/v1/your-path/**").permitAll()
```

### 2.3 请求返回 502 / 503

**可能原因**：
1. chat-web 服务挂了
2. chat-web 端口不对 (Nginx upstream 指向错误)
3. 内网不通 (Nginx 服务器无法连接 Milvus 服务器)

**排查步骤**：
```bash
# 1. 确认 web 进程存活
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "ps aux | grep 'chat-web' | grep -v grep"

# 2. 确认端口监听
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "netstat -tlnp | grep 8081"

# 3. 确认内网连通
ssh -i "/Users/apple/Downloads/我的密钥.pem" root@112.124.106.108 \
  "curl -s -o /dev/null -w '%{http_code}' http://172.23.172.13:8081/actuator/health"

# 4. 重启 web
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-web.sh"
```

### 2.4 LLM 调用失败

1. API Key 过期或额度用尽
2. 网络超时
3. LLM 返回格式异常（控制字符、gzip 乱码等）
4. 线程池满导致任务被丢弃

**排查步骤**：

**常见修复**（如需要修改代码）：
详见 `docs/LLM策略与路由说明.md` 的已知问题章节。

### 2.8 JDK 26 编译失败 (cannot find symbol)

**现象**：`mvn clean install` 报 `cannot find symbol: variable Locale / HashMap / ModelConfig` 等

**原因**：JDK 26 更严格检查显式 import，不再允许未声明 import 的类型引用

**修复**：为报错文件添加对应的 `import` 声明：
```java
import java.util.Locale;           // Locale.ROOT
import java.util.HashMap;          // new HashMap<>()
import java.util.ArrayList;        // new ArrayList<>()
import java.util.HashSet;          // new HashSet<>()
import java.util.Arrays;           // Arrays.asList()
import java.util.Set;              // Set<String>
```

**已修复文件** (2026-08)：
- `chat-core`: `ErrorType.java`, `FileContentExtractor.java`, `DocumentParser.java`, `TreeHoleService.java`, `LLMStrategyFactory.java`, `TaskClassifier.java`
- `chat-media`: `MediaGenController.java`

## 三、意图识别漏斗排查

### 3.1 规则层未生效

**现象**：日志中没有 `[RuleMatcher]` 命中记录

**排查**：
```bash
# 1. 确认规则文件是否加载
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep 'RuleMatcher.*加载' /opt/app/logs/core-9090.log | tail -3"

# 应该看到类似:
# [RuleMatcher] 从 intent-rules.json 加载 10 条规则
# [RuleMatcher] 规则加载完成: keywords=5 regex=5 stateRules=0
```

**如果未加载**：确认 `chat-core/src/main/resources/intent-rules.json` 已打包到 jar 中。

### 3.2 语义层 L2 不工作

**现象**：没有 `[ContextMatcher]` 日志，或命中率为 0

**排查**：
```bash
# 确认 RAG/Milvus 是否启用
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -c 'ContextMatcher' /opt/app/logs/core-9090.log"
```
- L2 依赖 `app.rag.enabled=true` 和 Milvus 可用
- 如果没有 `intent_examples` 集合数据，L2 不会命中（自动降级到 L3）

### 3.3 查看三层命中分布

```bash
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -o 'L[1-3]' /opt/app/logs/core-9090.log | sort | uniq -c"
```

**正常分布**：L2 最多，L1/L3 较少。如果 L3 占大多数，说明规则层和语义层缺少数据。

## 4. 知识库管理 (RAG)

### 4.1 知识库列表显示 internal server error

**排查**：

```bash
# 1. 查看 chat-web 最近错误
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -i 'ERROR\|Exception' /opt/app/logs/web-8081.log | tail -10"

# 2. 查看 chat-core 最近错误
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep -i 'ERROR\|Exception' /opt/app/logs/core-9090.log | tail -10"
```

**常见原因**：

| 错误 | 原因 | 解决 |
|------|------|------|
| `MismatchedInputException: Cannot deserialize Array as Map` | `CoreClient` 用了 `Map.class` 接收数组返回值 | 改为 `Object.class`，已修复 |
| `403 "访问被拒绝"` (非 "仅管理员可操作知识库") | `chat-web` → `chat-core` 缺少 `User-Agent` 头，被 `IpRateLimitInterceptor` 拦截 | `authHeaders()` 中加 `User-Agent: chat-web`，已修复 |
| `403 "仅管理员可操作知识库"` | JWT 中 `role` 不是 `admin` | 数据库 `UPDATE users SET role='admin' WHERE name='xxx'`，重新登录获取新 Token |
| `404 not found` / 路由不存在 | `chat-web` 没有 `/api/v1/rag/*` 代理路由 | 检查 `KnowledgeBaseController` 是否存在 |
