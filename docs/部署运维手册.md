## 二、本机开发部署

### 2.1 前置准备

```bash
# 安装 Redis
brew install redis && brew services start redis

# 安装 RabbitMQ
brew install rabbitmq && brew services start rabbitmq

# Node.js 18+ (通过 nvm 管理)
nvm install 18 && nvm use 18
```

### 2.2 打包全部模块

```bash
cd /Users/apple/IdeaProjects/chat-system-project
mvn clean install -DskipTests
```

### 2.3 启动服务（至少两个终端）

**终端 1 - chat-core（端口 9090）**：
```bash
cd /Users/apple/IdeaProjects/chat-system-project
java -jar chat-core/target/chat-core-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=local --server.port=9090
```

**终端 2 - chat-web（端口 8080）**：
```bash
cd /Users/apple/IdeaProjects/chat-system-project
java -jar chat-web/target/chat-web-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=local --server.port=8080 \
  --app.core.base-url=http://127.0.0.1:9090
```

**终端 3 - 前端开发**：
```bash
cd frontend && npm run dev
```

### 2.4 访问地址

| 服务 | 地址 |
|------|------|
| 前端页面 | http://localhost:5173 |
| Web API | http://localhost:8080/api/v1/* |
| Core 内部 API | http://localhost:9090/internal/* |

## 三、生产服务器部署

### 3.1 SSH 密钥

| 用途 | 密钥路径 |
|------|---------|
| 主服务器 (112.124.106.108) | `/Users/apple/Downloads/我的密钥.pem` |
| Milvus 服务器 (121.40.188.98) | `/Users/apple/Downloads/Milvus.pem` |

### 3.2 部署流程

```bash
# 1. 构建前端
cd /Users/apple/IdeaProjects/chat-system-project/frontend
npm run build

# 2. 打包全部后端模块
cd /Users/apple/IdeaProjects/chat-system-project
mvn clean install -DskipTests

# 3. 上传 jar 到 Milvus 服务器
scp -i "/Users/apple/Downloads/Milvus.pem" \
  chat-core/target/chat-core-0.0.1-SNAPSHOT.jar \
  root@121.40.188.98:/opt/app/core/

scp -i "/Users/apple/Downloads/Milvus.pem" \
  chat-web/target/chat-web-0.0.1-SNAPSHOT.jar \
  root@121.40.188.98:/opt/app/web/

scp -i "/Users/apple/Downloads/Milvus.pem" \
  chat-games/target/chat-games-0.0.1-SNAPSHOT.jar \
  root@121.40.188.98:/opt/app/games/

scp -i "/Users/apple/Downloads/Milvus.pem" \
  chat-media/target/chat-media-0.0.1-SNAPSHOT.jar \
  root@121.40.188.98:/opt/app/media/

# 4. 上传前端静态资源到主服务器 Nginx
scp -r -i "/Users/apple/Downloads/我的密钥.pem" \
  frontend/dist/* \
  root@112.124.106.108:/opt/app/static/chat/
```

### 3.3 重启服务

```bash
# 单独重启（改了哪个重启哪个）
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-core.sh"      # 重启 core
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-web.sh"       # 重启 web (仅 8081)
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-games.sh"     # 重启 games
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-media.sh"     # 重启 media

# 全量重启
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "bash /opt/app/restart-all.sh"
```

### 3.4 环境变量

所有 start/restart 脚本都加载 `/opt/app/.env` 文件，包含：
- `DB_USERNAME` / `DB_PASSWORD` — MySQL 连接凭据
- `REDIS_HOST` / `REDIS_PORT` — Redis 连接
- `RABBITMQ_HOST` / `RABBITMQ_PORT` — RabbitMQ 连接
- LLM API Key（千问、DeepSeek、豆包）

### 3.5 意图识别配置

| 环境变量 | 默认值 | 说明 |
|---------|-------|------|
| `INTENT_ENABLED` | `true` | 是否启用意图识别 |
| `INTENT_MODEL` | `qwen-turbo` | L3 分类用 LLM 模型 |
| `INTENT_CTX_THRESHOLD` | `0.75` | L2 语义匹配阈值 |
| `INTENT_CTX_TOPK` | `5` | L2 k-NN 检索数量 |
| `INTENT_AUTO_EXTRACT` | `false` | 是否启用自动规则挖掘 |

规则热更新：
```bash
# 修改 intent-rules.json 后无需重启 core，调用管理接口即可
# (管理接口预留中)
```

查看漏斗命中率：
```bash
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep 'IntentFunnel\|RuleMatcher\|ContextMatcher\|ToolMatcher' /opt/app/logs/core-9090.log | tail -20"
```

### 6.2 思考链展示排障

```bash
# 查看 ParsingStream 相关日志
ssh -i "/Users/apple/Downloads/Milvus.pem" root@121.40.188.98 \
  "grep 'ThinkingStream\|thinking_start\|isComplexIntent' /opt/app/logs/core-9090.log | tail -20"
```

**常见问题**：

| 现象 | 可能原因 | 排查方式 |
|------|---------|---------|
| 复杂问题无灰色思考链 | LLM 未输出 `<thinking>` 标签 | 查看 LLM 原始输出确认是否包含标签 |
| 思考链内容中断/不完整 | 流式输出标签被 cross-chunk 切断 | `emitSafe()` 缓冲 11 字符防此问题，检查 LLM 原始输出 |
| 简单问题也出现灰色区域 | 意图误判为复杂意图 | 查看 `IntentFunnel` 日志确认最终意图 |
| 前端无渲染 | 前端未处理 `thinking_token` | 检查浏览器 WebSocket 消息，确认消息类型 |

> **Note**：思考链功能内置于 ChatProcessor / TreeHoleService，无需额外配置或重启，部署后自动生效。
