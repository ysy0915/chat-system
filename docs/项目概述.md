# 博思AI智能体 — 项目概述

---

## 一、目标用户

| 用户群体 | 典型场景 | 核心需求 |
|----------|---------|---------|
| **普通用户** | 日常对话、知识问答、情绪倾诉 | 需要一个能聊得来、有温度、不敷衍的 AI 伙伴 |
| **深度思考者** | 复杂问题决策、观点辩论、多角度分析 | 想要多个 AI 从不同立场展开辩论，帮助看清问题全貌 |
| **内容创作者** | 配图生成、短视频制作、3D 模型产出 | 用自然语言描述就能生成图片/视频/3D 素材，降低创作门槛 |
| **开发者 / 学习者** | 代码生成、文档检索、知识问答 | 需要 AI 理解技术上下文，结合文档知识库给出精准答案 |
| **游戏玩家** | 与 AI 对战或协作的休闲游戏 | 在聊天应用中体验 AI 驱动的多人对战，社交 + 娱乐一体 |

---

## 二、核心用户诉求

用户在使用现有 AI 产品时面临 6 个根本性问题：

1. **单一模型偏见**：一个模型一种观点，用户只能听到单方说辞，无法获得多元视角
2. **黑盒推理**：AI 给出答案但不展示思考过程，用户无法判断结论是否可靠
3. **意图识别粗暴**：所有问题用同一套参数处理，简单对话和复杂推理混为一谈，响应慢、体验差
4. **能力孤岛**：聊天、绘画、视频、游戏分散在不同平台，切换成本高，数据不互通
5. **稳定性焦虑**：LLM 调用经常报错、超时，用户被晾着等，没有自愈机制
6. **安全与体验矛盾**：不防刷被滥用，防太死影响正常使用，缺乏智能化的安全策略

## 三、解决方案

博思AI 是一个**多模型智能协作平台**，核心理念是「不只一个 AI 回答你，而是一群 AI 一起帮你」。

```
                            ┌──────────────┐
                            │   前端 SPA    │
                            │  React + Vite │
                            └──────┬───────┘
                                   │ HTTP / WebSocket
                            ┌──────▼───────┐
                            │   chat-web   │  网关层
                            │  限流·认证·路由 │
                            └──────┬───────┘
                                   │ Nacos 服务发现
         ┌───────────────┬─────────┼─────────┬──────────────┐
         ▼               ▼         ▼         ▼              ▼
   ┌──────────┐   ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
   │ chat-core│   │chat-games │ │chat-media│ │ chat-llm │ │  Milvus  │
   │ AI 核心   │   │ 多人游戏  │ │ 多模态   │ │ LLM 服务 │ │  知识库  │
   └──────────┘   └──────────┘ └──────────┘ └──────────┘
         │
    ┌────┴────┬──────────┬──────────┐
    ▼         ▼          ▼          ▼
  豆包    DeepSeek     千问     其他模型
```

**四大支柱能力**：

| 支柱 | 解决什么 | 如何做到 |
|------|---------|---------|
| **多方辩论** | 单一模型偏见 | 标准辩论 (三方 3 轮) + 树状辩论 (LLM 拆解视角 → 并行辩论 → 汇总) |
| **意图漏斗** | 粗暴参数匹配 | L1 规则 (0-1ms) → L2 语义 (30-80ms) → L3 LLM 分类，按意图自动调参 |
| **思考链** | 黑盒推理 | ThinkingStreamParser 状态机实时剥离推理过程，仅展示不存库 |
| **全能力融合** | 能力孤岛 | 同一入口聊天 / 辩论 / 游戏 / 图片 / 视频 / 3D / 知识库，统一鉴权 |

## 四、创新点

### 1. 意图识别三层漏斗

```
请求 → L1 规则匹配 (0-1ms) → 命中? → 返回意图
              │ 未命中
              ▼
         L2 语义匹配 (30-80ms) → 置信度>0.7? → 返回意图
              │ 未命中
              ▼
         L3 LLM 分类 (200-1000ms) → 兜底返回 UNKNOWN
```

- 首创按命中概率分配计算资源的三级漏斗
- 规则热加载 + 自动挖掘（多级 TF-IDF 阈值 0.05/0.08/0.15 → LLM 标注意图）
- 意图驱动 Temperature：代码 0.2、创意 0.95、翻译 0.1，自动匹配
- 10 种意图全覆盖：33 条 L1 规则 + ~420 条 L2 种子示例
- **自增强闭环**：L3 高置信结果 → SeedPool → 自动灌入 L2 (Milvus) + L1 (Trie)
- **L2 动态阈值**：滑动窗口追踪每意图命中率，自动 ±0.02 调节
- L1+L2 综合命中率目标 >95%，仅 <10% 走 LLM 兜底

### 2. 树状辩论 — LangGraph 混合编排

```
用户提问 → LLM 拆解为 2-3 个分析视角
                │
      ┌─────────┼─────────┐
      ▼         ▼         ▼
   视角A      视角B      视角C        ← Java 并行调度
      │         │         │
   ┌──┴─────────┴─────────┴──┐
   │  LangGraph StateGraph    │        ← 每视角内图式循环
   │  debate → shouldContinue │
   │    ↑           ↓         │
   │    └── (round < 3)       │
   │              (round≥3) → │
   │          summary → END   │
   └──────────────────────────┘
      │         │         │
   视角结论   视角结论   视角结论
      └─────────┼─────────┘
                ▼
           LLM 综合汇总
```

- LangGraph4j `StateGraph` 做视角内循环编排，Java `CompletableFuture` 做视角间并行
- 混合模式兼顾结构化编排和运行时灵活性（视角数量由 LLM 动态决定）
- 容错设计：单视角失败不影响其他视角，汇总 LLM 失败自动本地拼接

### 3. 思考链实时展示

- 三态状态机逐 token 分离 `<thinking>...</thinking>` 和普通内容
- 零延迟 emit：仅缓冲最后 11 字符用于模式匹配，其余即时推送
- 安全降级：300 字符无标签自动切非思考模式，避免误判
- 意图驱动触发：复杂意图自动开启，简单对话跳过
- 仅实时展示，不存入数据库，保持历史记录干净

### 4. AI 错误自愈

| 错误类型 | 自愈策略 |
|---------|---------|
| 频率限制 / 超时 | 换同 Provider 其他模型重试 |
| 认证失败 | 跳过失败模型，用默认模型重试 |
| 网络错误 | 等待 1s 后重试 |
| 解析错误 | 降 temperature 到 0.3 重试 |
| 模型不存在 | 不重试，直接报错 |

叠加 Resilience4j CircuitBreaker（50% 失败率 → 30s 熔断）形成双层防御。

### 5. 多层限流安全

```
IP 全局限流 600次/分钟
    └── 用户级限流 20次/分钟 / 200次/小时
            └── 敏感接口限流 10次/分钟
                    └── 自动拉黑 1000次/60s → 封禁 10min
```

加上 UA 爬虫过滤 + CORS 白名单 + CSP 防 XSS，Fail-open 容错（Redis 异常放行）。

## 五、开放 / 复用价值

| 维度 | 说明 |
|------|------|
| **模块化架构** | 6 个微服务松耦合（core/web/llm/games/media + flink），LLM 调用已拆分为 chat-llm 独立服务，意图漏斗、思考链解析器等模块可复用 |
| **LangGraph 混合模式** | 为「编译时静态节点 + 运行时动态并行」场景提供了可参考的实现范式 |
| **Fluent Builder API** | `llmClient.forConfig(model).scene("chat").stream().execute()` 风格统一，降级、重试、熔断内聚 |
| **多 Provider 策略模式** | 新增 LLM Provider 只需实现 `LLMProviderStrategy` 接口并注册，不影响现有模型 |
| **三层意图漏斗** | 规则层可独立部署为轻量意图网关，语义层复用 Embedding 模型 |
| **前后端完全分离** | 前端独立构建部署，API/WS 路径统一管理，可作为同类项目的脚手架 |
| **Docker 全栈部署** | 三套 Compose 文件覆盖开发 / 生产 / 全量场景，开箱即用 |
| **单元测试 + Checkstyle + PMD** | 空壳测试已全部清理，代码质量有保障，CI/CD 流水线可复用 |
