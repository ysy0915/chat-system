## 一、MySQL 表结构

### 1.1 核心业务表

#### `users` — 用户表

```sql
CREATE TABLE users (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  email        VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  name         VARCHAR(100),
  role         VARCHAR(32) DEFAULT 'user',
  created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at   TIMESTAMP NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 说明 |
|------|------|
| role | `user` / `admin` |

---

#### `messages` — 消息表

```sql
CREATE TABLE messages (
  id        BIGINT AUTO_INCREMENT PRIMARY KEY,
  req_id    CHAR(36) NOT NULL,
  user_id   BIGINT NOT NULL,
  question  TEXT NOT NULL,
  answer    JSON NULL,
  status    VARCHAR(32) NOT NULL,
  provider  VARCHAR(64) NULL,
  model     VARCHAR(128) NULL,
  metadata  JSON NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  UNIQUE KEY uq_messages_reqid (req_id),
  INDEX idx_user_created (user_id, created_at),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 说明 |
|------|------|
| `req_id` | UUID v4，幂等键，防止重复处理 |
| `status` | `queued` / `processing` / `done` / `failed` |
| `answer` | JSON 格式，包含各模型回复 |
| `metadata` | 扩展字段（客户端语言、trace_id 等） |

#### ~~`model_configs`~~ — 模型配置表（[B档] 已删除）

> 🗑 2026-08-13 迁移后退役、同日从生产库 DROP（备份 `/opt/app/backup/deprecated_tables_20260813.sql`）。运行时统一读取 `llm_provider_config` / `llm_provider_props` / `llm_model_config` / `llm_model_props` 四张新表（见 `llm_routing_schema.sql`）。数据迁移脚本 `migrate_model_configs_to_llm.sql` 保留作历史参考，模型 id 保持一致。下方保留原表结构仅作历史追溯。

```sql
CREATE TABLE model_configs (
  id                BIGINT AUTO_INCREMENT PRIMARY KEY,
  provider          VARCHAR(64) NOT NULL,
  model             VARCHAR(128) NOT NULL,
  api_key_encrypted TEXT NOT NULL,
  meta              JSON NULL,
  priority          INT DEFAULT 100,
  enabled           BOOLEAN DEFAULT TRUE,
  created_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 说明 |
|------|------|
| `provider` | 模型提供商 (qwen / deepseek / doubao) |
| `api_key_encrypted` | 加密存储的 API Key（迁移后存于 `llm_provider_props`） |
| `priority` | 路由优先级，数值越小优先级越高（迁移后存于 `llm_model_config.priority`） |
| `enabled` | 是否启用，可运行时切换（迁移后存于 `llm_model_config.enabled`） |
| `meta` | 额外参数 (baseUrl, temperature, maxTokens 等)（baseUrl 迁移后存于 `llm_model_props` / `llm_provider_config.base_url`） |

新表映射关系：

| ModelConfig 视图 | 新表来源 |
|------|------|
| `id` | `llm_model_config.id`（与旧 id 一致） |
| `provider` | `llm_provider_config.provider_name` |
| `model` | `llm_model_config.model_name` |
| `apiKeyEncrypted` | `llm_provider_props`(prop_key='api_key').prop_value |
| `metaJson.baseUrl` | `llm_model_props`(prop_key='base_url') → 回退 `llm_provider_config.base_url` |
| `modelType` | `llm_model_config.model_type`（沿用旧枚举） |

### 1.2 功能模块表

#### `rag_knowledge_bases` — 知识库表

```sql
CREATE TABLE rag_knowledge_bases (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '知识库ID',
    name            VARCHAR(100) NOT NULL COMMENT '知识库名称',
    description     VARCHAR(500) DEFAULT '' COMMENT '描述',
    document_count  INT DEFAULT 0 COMMENT '文档数量',
    total_chunks    BIGINT DEFAULT 0 COMMENT '总分片数',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 说明 |
|------|------|
| `document_count` | 冗余计数，方便列表展示 |
| `total_chunks` | 总向量分片数（Milvus 索引量） |

#### `rag_documents` — 知识库文档表

```sql
CREATE TABLE rag_documents (
    id                BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '文档ID',
    knowledge_base_id BIGINT NOT NULL COMMENT '所属知识库ID',
    file_name         VARCHAR(255) NOT NULL COMMENT '原始文件名',
    source            VARCHAR(512) DEFAULT '' COMMENT '来源标记',
    chunk_count       INT DEFAULT 0 COMMENT '分片数量',
    file_size         BIGINT DEFAULT 0 COMMENT '文件大小(字节)',
    status            VARCHAR(20) DEFAULT 'pending' COMMENT 'pending/processing/done/error',
    error_message     TEXT COMMENT '失败原因',
    created_at        DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_kb_id (knowledge_base_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 说明 |
|------|------|
| `status` | `pending` → `processing` → `done` / `error` |
| `chunk_count` | 切分后写入 Milvus 的向量条数 |

#### `debate_records` — 辩论记录表

存储观点辩论场的对话记录，包含辩题、各方观点、用户追问等。

#### `treehole_messages` — 情绪树洞表

存储用户的情绪倾诉内容、AI 回复、心情标签等。

#### `media_gen_records` — 多模态生成记录表

存储文生图、文生视频、图生 3D 的生成任务记录和结果 URL。

#### `online_count_records` — 在线人数历史快照

监控页数据源，按时间点记录各页面在线人数。

#### `attachments` — 附件表

```sql
CREATE TABLE attachments (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  message_id BIGINT NULL,
  uploaded_by BIGINT NOT NULL,
  storage_url VARCHAR(1024) NOT NULL,
  mime_type  VARCHAR(128),
  filename   VARCHAR(255),
  size       BIGINT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (message_id) REFERENCES messages(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 二、索引策略

| 表 | 索引 | 类型 | 用途 |
|----|------|------|------|
| `messages` | `uq_messages_reqid` | UNIQUE | 幂等防重 |
| `messages` | `idx_user_created` | 联合索引 | 用户历史查询 |
| `messages` | `idx_status` | 普通索引 | 按状态查询 |
| `messages` | `ft_messages_content` | FULLTEXT | 关键词搜索（`MATCH ... AGAINST`，替代 `LIKE '%kw%'` 全表扫描） |
| `users` | `UNIQUE(email)` | UNIQUE | 登录查询 |
| ~~`model_configs`~~ | `INDEX(provider, model)` | 联合索引 | 🗑 已删除（2026-08-13），模型查找由 `llm_model_config`/`llm_provider_config` 承担 |
| `treehole_messages` | `INDEX(user_id)` | 普通索引 | 用户树洞历史 |

> 迁移脚本位置：`docs/db-migrations/V1.1.0__add_messages_index.sql`
> 全文索引迁移：`docs/sql/fulltext_search_indexes.sql`（2026-08 新增，解决消息搜索性能问题）

#### `rag_chunks`（BM25 关键词分片表，2026-08-15 新增）

混合检索（向量 + 关键词）的关键词侧存储，由 chat-llm `KeywordSearchService` 启动幂等建表（`CREATE TABLE IF NOT EXISTS`），**无需手工迁移**。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT AUTO_INCREMENT PK | 主键 |
| `kb_id` | BIGINT NOT NULL | 知识库 ID |
| `doc_id` | BIGINT NOT NULL | 文档 ID |
| `chunk_index` | INT NOT NULL | 分片序号（文档内从 1 递增） |
| `source` | VARCHAR(512) | 来源文件名 |
| `page` | INT | 页码（PDF 逐物理页，默认 0） |
| `text` | MEDIUMTEXT NOT NULL | 分片文本（全文索引目标） |
| `created_at` | DATETIME | 创建时间 |

- 索引：`idx_kb_doc(kb_id, doc_id)`、`FULLTEXT ft_rag_text(text) WITH PARSER ngram`（中文二元分词，MySQL 5.7.6+/8.0）
- 写入/检索/删除仅在 `HYBRID_KEYWORD_ENABLED=true` 时生效；删除知识库/文档时按 `kb_id`/`doc_id` 联动清理

## 三、Redis 键设计

### 3.1 会话跟踪

| 数据结构 | Key 模式 | 说明 | TTL |
|---------|---------|------|-----|
| ZSet | `session:{page}` | 页面在线用户集合，score=时间戳 | — |
| String | `online:count:{page}` | 页面实时在线人数 | — |

### 3.2 结果缓存

| 数据结构 | Key 模式 | 说明 | TTL |
|---------|---------|------|-----|
| Hash | `model:cache:{reqId}` | AI 回复结果缓存 | 24h |

### 3.3 用户数据

| 数据结构 | Key 模式 | 说明 | TTL |
|---------|---------|------|-----|
| List | `user:{uid}:history` | 用户消息 ID 列表 (LPUSH, LTRIM) | — |

### 3.4 并发控制

| 数据结构 | Key 模式 | 说明 | TTL |
|---------|---------|------|-----|
| String | `inflight:{req_id}` | 消费锁 (SETNX)，防止重复消费 | 60-300s |

### 3.5 限流

| 数据结构 | Key 模式 | 说明 |
|---------|---------|------|
| Counter | `rate:{uid}` | 用户请求速率计数器 |

### 3.6 Multi-Agent 工作流状态（2026-08 新增）

| 数据结构 | Key 模式 | 说明 | TTL |
|---------|---------|------|-----|
| String | `agent:plan:{planId}` | 拆解计划（`SubAgentPlan` JSON，供任意实例收敛） | 30min |
| String | `agent:plan:{planId}:meta` | 请求元信息（reqId/userId/question/模型参数） | 30min |
| String | `agent:plan:{planId}:total` | 子任务总数（Worker 收敛触发依据） | 30min |
| String | `agent:plan:{planId}:received` | 已回收结果数（INCR 原子计数） | 30min |
| String | `agent:plan:{planId}:lock` | 收敛分布式锁（SETNX：正常触发 2min / Reconciler 对账 5min） | 2/5min |
| String | `agent:plan:{planId}:converged` | 收敛完成标记（Reconciler 去重，防重复触发） | 30min |
| Hash | `agent:subtask:result:{planId}` | 子任务结果聚合（field=taskId，value=`SubAgentResult` JSON，幂等覆盖） | 30min |
| Counter | `agent:workflow:active` | 全局并行工作流计数（Lua INCR/DECR 原子限流，上限 max-concurrent=8，双实例共享） | 300s |

> 说明：工作流状态全部存 Redis（30min TTL），跨实例收敛依赖这些键；`agent:workflow:active` 用 Lua 脚本保证双实例计数原子性，超限请求自动降级普通流程。

迁移脚本位于 `docs/db-migrations/` 和 `docs/sql/`：

## 五、MQ 消息格式

### RabbitMQ 消息体

Exchange: `chat.exchange`
Routing Key: `chat.request`

```json
{
  "req_id": "uuid-v4",
  "user_id": 123,
  "question": "用户问题文本",
  "attachments": [{"id": 45, "url": "..."}],
  "preferred_model_config_id": 7,
  "timestamp": 1690680000,
  "metadata": {
    "clientLang": "zh",
    "trace_id": "..."
  }
}
```

角色与职责：
- **生产者**：`MessageController.createMessage()` 入库后发布
- **消费者**：`ChatProcessor.process()` 消费处理
- **容错**：RabbitMQ 不可用时直接同步调用 `chatProcessor.process()` 降级
